= Add a Briefcase action

This recipe adds a *Check before sharing* action for the files that the user selects in Briefcase. The action tests each selected file against a sharing policy, no executable files and nothing over 10 MB, and lists the result in a dialog. Use it when an action works on the selected files and belongs next to *Download* and *Delete*. The action is offered in two places, the context menu of a file and the toolbar above the list, and both use the same logic. Each is a small component that a xref:reference/glossary.adoc#zimlet[Zimlet] registers for a slot of the xref:reference/glossary.adoc#modern-ui[Modern UI] Briefcase.

[#what-you-will-learn]
== What you will learn

* Choose a slot for file actions.
* Offer one action as a menu item and a toolbar button.
* Handle a selection of folders and files.
* Show the result in a dialog.

[#before-you-start]
== Before you start

* Follow xref:build-by-goal.adoc#before-every-recipe[Required reading before every recipe].
* Files and a folder in Briefcase to select. The check in the example needs a file named `setup.exe`, of any content, to show a failed result.

[#choose-the-slot]
== Choose the slot

Three slots add an action for the selected files. Choose the slot by where the user looks for the action. The example offers one action in the context menu of a file and in the toolbar, so it fills two of them. Look up each slot in the xref:reference/slots.adoc[slot index].

[#the-slots]
=== The slots

`slot::briefcase-document-context-menu`::
The context menu of a file, at its end, after *Delete*. Return a menu item. The menu opens for a file, and not when the selection holds both files and folders.

`slot::briefcase-document-header-action`::
The toolbar above the list, after *Download*, *Move* and *Delete* and before the menu with three dots. Return a button. The toolbar is shown whether or not a file is selected, so the handler also runs for an empty selection.

[#other-slots]
=== Other slots

`slot::action-menu-briefcase-more`::
The menu with three dots at the end of the toolbar, before the *Tag* item. Return a menu item. Choose it instead of the toolbar button for an action that the user needs less often. It passes `selectedList`, `disableRename`, `errorCode` and `isSelectedFolder`. The menu is off while nothing is selected, and it is not in the folder *Files shared with me*. The same menu item component works here as in the context menu.

`slot::briefcase-upload-button`::
The upload button of the sidebar. It is not for an action on selected files, and it passes `folder`, `documentRefetchQueries` and `disabled`, and not `selectedList`.

[#selection]
=== What `selectedList` holds

Each slot passes the selection to your handler as the xref:fundamentals/extending-the-ui.adoc#props-and-payload[prop] `selectedList`, a list of the selected items. The context menu also passes `disableRename`, `isFileSharedFolder` and `errorCode`. The toolbar also passes `isFileSharedFolder` and `errorCode`. The items are the selected rows of the list. A file has `id`, `name`, `size` in bytes, `contentType`, `version` and `tagNames`, among others. A folder has the field `absFolderPath`, and a file does not. The Modern UI tells the two apart in the same way.

* In the toolbar, `selectedList` can hold files, folders or both, because the user can select both kinds.
* In the context menu, it holds the selected files.
* In the menu with three dots, it holds only the files of the selection. The Modern UI removes the folders before it calls the slot.

A handler for the toolbar must therefore expect folders. The example keeps the files and ignores the rest.

The other props are not used by the example:

`isFileSharedFolder`::
`true` when the open folder is *Files shared with me*.

`disableRename`::
`true` when the Modern UI turns off its own *Rename* for the selection.

`errorCode`::
`404` when the preview of a file in a shared folder shows that the file no longer exists.

`isSelectedFolder`::
`true` when the first selected item is a folder.

When one is selected, the Modern UI shows its own *Edit* item or button only if no Zimlet returns content for the slot. [#expected-result]
== Expected result

* *Check before sharing* is in the context menu of a file and in the toolbar, after *Delete*.
* The action lists every selected file with *Ready to share* or the reason that it fails.
* A file with a blocked extension, or larger than 10 MB, fails the check.
* The toolbar button is turned off when the selection holds no file.

[#if-it-did-not-work]
== If it didn't work

The action is not in the menu or in the toolbar.::
* Cause: The Zimlet is not loaded, or a handler is registered under another key. The Modern UI does not check keys, so a misspelled key adds nothing and shows no error.
* Fix: Check that the sideloader shows the Zimlet as *Running*. Check that the keys are `slot::briefcase-document-context-menu` and `slot::briefcase-document-header-action` and that you register in `init()`. Reload the page.

The context menu has no action for a selection of files and folders.::
* Cause: The Modern UI does not open the file context menu when the selection holds both files and folders, so the slot is not called.
* Fix: Use the toolbar button, which is shown for every selection, and ignore the folders as `get-files.js` does.

The dialog shows keys such as `my-zimlet.dialogTitle`.::
* Cause: The component is not wrapped with `withIntl`, or `en_US.json` lacks the keys. The dialog is drawn outside your Zimlet and cannot find its texts without the wrapper.
* Fix: Wrap the component with `withIntl()` and merge the texts into `src/intl/en_US.json`.

*Edit* is missing for a Zimbra document.::
* Cause: A handler of the slot returns an element for a single Zimbra document, so the Modern UI no longer shows its own *Edit*.
* Fix: Return `null` from the handler when `selectedList` holds one item whose `contentType` includes `application/x-zimbra-doc`.
