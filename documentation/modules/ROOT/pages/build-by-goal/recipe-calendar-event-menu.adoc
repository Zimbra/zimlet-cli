= Add an action to a calendar event menu

This recipe adds an *Export as .ics file* item to the menus of a calendar event in the xref:reference/glossary.adoc#modern-ui[Modern UI]. Choosing it downloads the event as an iCalendar file, a file with the extension `.ics` that other calendar apps can open. Use it when an action belongs to one event. The user then finds it next to *Move*, *Copy* and *Show Original*, and does not need a screen of your own. The item is a small component that a xref:reference/glossary.adoc#zimlet[Zimlet] registers for the two slots of the event menus.

[#what-you-will-learn]
== What you will learn

* Add an item to the context menu of an event and to the menu of an open event.
* Read the event that the menu belongs to.
* Download a file from the server with a name that you choose.

[#before-you-start]
== Before you start

* Follow xref:build-by-goal.adoc#before-every-recipe[Required reading before every recipe].
* An event in your calendar. To see how the file name is built, give it a title with a colon or a slash, such as `Review: Q3/Q4`.

[#choose-the-slot]
== Choose the slot

The item must be in the menu that opens when the user right-clicks an event, and in the menu of an event that is open. The example therefore fills the two slots of the event menus with the same item.

[#the-slots]
=== The slots

`slot::action-menu-event-context-menu`::
The context menu of an event, which opens when the user right-clicks an event in the calendar. The item comes at the end of the first group, after *Show Original*.

`slot::action-menu-event-more`::
The *More Options* menu with three dots, in the toolbar above an open event. The item comes at the end of the first group, after *Show Original*. The toolbar has this menu in the desktop layout only.

Look up the slots in the xref:reference/slots.adoc[slot index].

[#other-slots]
=== Other slots

`slot::action-menu-mail-more`::
The menus of a message. Choose it for an action on a message, as xref:build-by-goal/recipe-mail-action-menu.adoc[Add a mail menu item] shows.

`slot::calendar-appointment-edit-video-call`::
The form in which the user creates or edits an event. Choose it for a control that sets a value of the event, as xref:build-by-goal/recipe-appointment-field.adoc[Enhance the event location field] shows.

[#action-menu-item]
=== The ActionMenuItem component

`ActionMenuItem` draws one entry of an action menu. The recipe xref:build-by-goal/recipe-gear-and-settings-menu.adoc#action-menu-item[Add menu items to the app] explains it. This example uses two props:

`onClick`::
Runs when the user chooses the item. It starts the download.

`nonOfflineDesktopFeature`::
Turns the item off while the desktop app of the Modern UI is offline, because the download needs the server. The item stays on in a browser.

The example sets no `icon`, because the built-in items of these menus have none.

[#register-the-item]
== Register the item

Register one handler for each slot in `init()`, as xref:fundamentals/factory-and-lifecycle.adoc#init[Factory and lifecycle] describes. The handler receives the props of the slot and passes them on to the component. The example takes `zimbraBatchClient` from the xref:fundamentals/host-context.adoc[context] in the factory and passes it down, and not the whole context. One handler serves both slots, so the two menus always show the same item.

[#verify]
== Verify the result

. Run the Zimlet with `npm start` and load it in the sideloader, as xref:run-package-deploy/run-and-debug.adoc#load-with-the-sideloader[Run and debug] describes. Wait for the status *Running*, and reload the Modern UI page first if the Zimlet was loaded before.
. Open *Calendar* and right-click an event. *Export as .ics file* is at the end of the first group, below *Show Original*.
+

[#expected-result]
== Expected result

* *Export as .ics file* is in the context menu of an event, and in the *More Options* menu of an open event.
* Choosing it downloads one `.ics` file with the title of the event as its name.

[#if-it-did-not-work]
== If it didn't work

The item is not in the menu.::
* Cause: The Zimlet is not loaded, or a handler is registered under another key. The Modern UI does not check keys, so a misspelled key adds nothing and shows no error.
* Fix: Check that the sideloader shows the Zimlet as *Running*. Check that the keys are `slot::action-menu-event-context-menu` and `slot::action-menu-event-more`, and that you register in `init()`. Reload the page and open the menu again.

The item is in the context menu but not in the *More Options* menu.::
* Cause: The window is too narrow. The toolbar of an open event has the *More Options* menu in the desktop layout only.
* Fix: Widen the browser window, and open the event again.

The browser downloads no file, or the file is empty.::
* Cause: The server did not return the event. The path or the id can be wrong.
* Fix: Open the network tab of the browser tools and find the request with `fmt=ics`. Check its status and the id in its address.
