= Subscribe to a calendar

This recipe lets users subscribe to a calendar from its web address in the xref:reference/glossary.adoc#modern-ui[Modern UI]. The example adds the item *Subscribe to a calendar* to a menu of the Calendar sidebar. The item opens a dialog that asks for the address of an iCalendar feed and for a name. The new calendar then shows in the group *Others*. Use the same pattern for any flow that starts in the Calendar sidebar and ends in a list of calendars of your own. A xref:reference/glossary.adoc#zimlet[Zimlet] adds the item, the dialog and the list by filling three xref:fundamentals/extending-the-ui.adoc[slots].

[#what-you-will-learn]
== What you will learn

You learn how to:

* Choose the three slots of a flow that starts in the Calendar sidebar.
* Open a dialog with a flag, and close it by removing the flag.
* Create a calendar from an address with a request to the server.
* List calendars of your own in the group *Others*, with the row that the Modern UI draws for a calendar.

[#choose-the-slots]
== Choose the slots

The Modern UI has no calendar subscription of its own, and it draws no group for a calendar that has the address of a feed. A flow therefore needs an item that starts it, a dialog that creates the calendar and a place where the calendar shows. The example fills one slot for each.

[#the-slots]
=== The slots

`slot::calendar-subscription-menu`::
The menu of the group *Others*, and the menu of the *Calendar* heading in a narrow window. The slot passes nothing to the handler. Look up the slot in the xref:reference/slots.adoc[slot index].

`slot::calendar-subscription-modal-flow`::
The Calendar screen. The slot draws all the time, and the Calendar passes a flag as `isActive` that says when the dialog must show. It also passes `refetchCalendars`, which loads the calendars again.

`slot::calendar-subscription-list`::
The end of each of the three groups of the sidebar. It passes `isActive`, which is `true` in the group *Others*, and `renderItem`, which draws the row of a calendar. See xref:reference/slots/calendar/calendar-view.adoc#subscription-slots[Subscription slots] for how the three work together.

[#other-slots]
=== Other slots

`slot::calendar-context-add-holiday`::
The *More Options* menu of the Calendar toolbar. Choose it for an action on calendars as a whole that must not depend on the group *Others*.

`slot::calendar-folder-list-end`::
Below the folder list of the sidebar. Choose it for calendars that the Modern UI does not draw and that need a group of their own. The holiday calendars of the user are an example.

For a dialog that has no relation to the Calendar, use `addModal`, as xref:build-by-goal/recipe-app-events.adoc[React to app events] shows.

[#open-the-dialog]
== Open the dialog with a flag

The item and the dialog are two handlers for two slots, so they cannot call each other. They share a flag in the store of the Modern UI instead. The item stores the flag with `addSlot`. The Calendar passes it to the dialog slot as `isActive`. The dialog removes it with `removeSlot` when it closes. See xref:reference/context/store/zimlet-redux/actions.adoc#add-slot[addSlot] and xref:reference/context/store/zimlet-redux/actions.adoc#remove-slot[removeSlot].

The Calendar reads the flag only under the id `calendar-subscription-modal-flow`. A flag under another id opens nothing.

[#draw-the-dialog]
== Draw the dialog

The dialog holds the address, the name, the error and whether the request is running. The handler returns it only while `isActive` is `true`. The slot draws all the time, so a handler that ignores the flag shows its dialog on every visit to the Calendar. Because the component leaves the screen when the flag goes, its fields start empty each time the dialog opens.

[#modal-dialog]
=== The ModalDialog component

`ModalDialog` is the frame of a dialog. xref:build-by-goal/recipe-app-events.adoc#modal-dialog[React to app events] explains it, and xref:reference/shims/components/dialogs.adoc#modal-dialog[Dialogs] lists every prop. This dialog asks for input, so it uses the buttons too:

`onAction` and `actionLabel`::
`onAction` runs when the user chooses the primary button. `actionLabel` is the id of the text on that button, taken from `en_US.json`.

`disablePrimary`::
Disables the primary button. The example disables it until both fields have text.

`pending`::
Shows a spinner and disables the primary button while the request runs. *Cancel* and the close button stay active.

`error`::
A message that the dialog shows above the content. It reports a wrong address and a failed request.

`onClose`::
Called for the close button, *Cancel*, the *Escape* key and a click outside the dialog. The dialog does not close itself, so this function removes the flag.

`autofocusChildIndex`::
The element that gets the focus when the dialog opens. The close button is the first, so `1` is the first field.

[#create-the-calendar]
== Create the calendar

A subscribed calendar is a folder of the view `appointment` that has an address. The `CreateFolder` request creates it, and the server fills it from the feed at `url`. The flag `#` marks the calendar as checked, so its events show. The request fails when the server cannot read the address, for example when the feed asks for a password. The dialog then shows its error. See xref:reference/context/batch-client/json-request.adoc[jsonRequest] for the options of the call.

[#list-the-calendars]
== List the subscribed calendars

The list reads the calendars of the user with `useCalendarsData`. A calendar that has an address and no owner is one that the user subscribed to. A calendar that another user shares has an owner, and a calendar of the user has no address. See xref:reference/shims/hooks/calendar-and-metadata.adoc#use-calendars-data[useCalendarsData] for the hook.

Draw every calendar with `renderItem`, which the slot passes. The row has the check box, the name and the menu of a calendar, as in the groups above. A row that you draw yourself lacks them.

[#limits]
== Know the limits

* The item shows in two menus, and the handler cannot tell which one opened. See xref:reference/slots/calendar/calendar-view.adoc#sidebar-menus[Sidebar menus].
* The group *Others* is closed when the sidebar first draws in a wide window. The new calendar shows after the user opens the group.
* The component lists every calendar that has an address and no owner. The Modern UI treats a calendar whose address contains the word `holiday` as a holiday calendar and passes it to `calendar-folder-list-end`. The component lists it as well, because it ignores the word.
* Any failure of the request shows the same message, whatever the reason.
* The example does not hide the item while the Modern UI is offline.
* The slots show the content of every handler. Enable only one Zimlet that fills these slots, or the user sees two items and two dialogs.

[#expected-result]
== Expected result

* The menu of the group *Others* has the item *Subscribe to a calendar*, and the item opens the dialog.
* A wrong address and a failed request show a message in the dialog, and the dialog stays open.
* A successful subscription closes the dialog and lists the calendar in the group *Others*.

[#if-it-did-not-work]
== If it didn't work

The item is missing.::
* Cause: The Zimlet is not loaded, or the handler is registered under another key. The Modern UI does not check keys, so a misspelled key adds nothing and shows no error.
* Fix: Check that the sideloader shows *Running*, that the key is `slot::calendar-subscription-menu` and that you register in `init()`. Reload the page.

The item does nothing.::
* Cause: The flag has another id than `calendar-subscription-modal-flow`, or the handler of the dialog slot ignores `isActive`.
* Fix: Use the id of `constants/index.js` in both places, and return `null` while `isActive` is not `true`.

The dialog shows on every visit to the Calendar.::
* Cause: The handler of `slot::calendar-subscription-modal-flow` does not check `isActive`.
* Fix: Return `null` unless `isActive` is `true`.

The dialog says that the calendar could not be added.::
* Cause: The server could not read the address, for example because the feed asks for a password.
* Fix: Open the address in a private browser window. If it asks for a password, use another address.

The calendar does not show in the sidebar.::
* Cause: The group *Others* is closed, the dialog did not call `refetchCalendars`, or the handler of the list ignores `isActive` and draws in another group.
* Fix: Open the group. Check that the dialog calls the function that the slot passes, and that the list returns `null` unless `isActive` is `true`.

The texts show as keys.::
* Cause: The texts are not merged into `src/intl/en_US.json`, or a component is not wrapped with `withIntl`.
* Fix: Merge the texts as the set up describes, and keep `withIntl()` around the item and the dialog.
