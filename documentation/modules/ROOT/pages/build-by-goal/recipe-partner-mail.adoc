= Mark senders

This recipe marks mail from partner organizations in the xref:reference/glossary.adoc#modern-ui[Modern UI]. A *Partner* badge appears beside the sender in the message list, and a *Partners* group in the folder list gives one link to each partner. Use the same pattern when a team must tell one kind of sender from the rest at a glance. The group keeps shortcuts for them within reach. A xref:reference/glossary.adoc#zimlet[Zimlet] adds both parts by registering one handler for each of two xref:fundamentals/extending-the-ui.adoc[slots].

[#what-you-will-learn]
== What you will learn

You learn how to:

* Choose the slots for a mark in the message list and a group in the folder list.
* Replace the sender names of a row for some messages only, and keep the standard names for all others.
* Draw a group that opens and closes like the groups of the folder list, with `FolderListGroup`.
* Keep the list of partners in one place, so that both parts use it.

== Before you start

* Follow xref:build-by-goal.adoc#before-every-recipe[Required reading before every recipe].

[#choose-the-slots]
== Choose the slots

The badge must sit beside the sender in the row, and the shortcuts belong with the folders of the user. The example therefore fills the slot of the sender names and the slot for a group of the folder list.

[#the-slots]
=== The slots

`slot::mail-sender`::
The sender names in every row of the message list, on every window width and in search results. The slot shows what the handlers return in place of the names, and shows the names when no handler returns a value. Look up the slot in the xref:reference/slots.adoc[slot index].

`slot::folder-group`::
The folder list of Mail, Calendar, Contacts and Briefcase. In Mail it sits below the *Folders* group and before the shared folders, the saved searches and the tags. The slot passes nothing to the handler. Look up the slot in the xref:reference/slots.adoc[slot index].

[#other-slots]
=== Other slots

`slot::folder-list-end`::
The bottom of the folder list, below the tags. Choose it for a tip or a note, and not for a group that belongs with the folders.

`slot::mail-sidebar-footer`::
Below the folder list in Mail only. Choose it when the content is of no use in Calendar, Contacts or Briefcase.

To add an item to the menus of a message, see xref:build-by-goal/recipe-mail-action-menu.adoc[Add a mail menu item].

[#mark-the-sender]
== Mark the sender

The slot passes three props. The example reads two of them. The slot also passes `viewType`, which the example does not use.

`emailAddresses`::
The names that the row shows by default, as an array of strings. Draw them again beside the badge.

`mailItem`::
The message or the conversation of the row. The example reads its senders to find the partner.

The slot replaces the names with what a handler returns. A component that adds a badge must therefore draw the names too. The handler returns the component only for a partner and returns `null` for every other row, so those rows keep the standard names. The slot calls the handler for every row of the list on every render. The handler therefore only calls the finder and holds no state.

[#folder-list-group]
=== The FolderListGroup component

`FolderListGroup` draws the heading of a group of the folder list, with an arrow, and shows its content below. It comes from `@zimbra-client/components`. Choose it for a group that must look and act like the groups of the folder tree.

*Without it:* a heading of your own is a `div` with a click handler. You draw the arrow, the keyboard support and the spacing yourself, and the group does not match the groups next to it.

*With it:* pass the key of the heading, the state and the content.

[source,js]
----
<FolderListGroup name="my-zimlet.partners" collapsed={collapsed} onToggle={handleToggle}>
	{links}
</FolderListGroup>
----

The example uses these props:

`name`::
The key of the heading text in your `en_US.json`, and not the text itself. The heading is empty when the dictionary has no such key.

`collapsed`::
Set it to `true` to hide the content and show the arrow in its closed state.

`onToggle`::
Called when the user chooses the heading or its arrow, or presses *Enter* on it. The group does not open or close by itself. Change `collapsed` in this function, as the example does.

The content is the `children` of the group, drawn below the heading while the group is open. See xref:reference/shims/components/navigation.adoc#folder-list-group[Navigation] for the other props.

The `Icon` component draws the arrow beside each link. xref:build-by-goal/recipe-message-banner.adoc#icon[Show a message banner] explains it.

[#limits]
== Know the limits

* The domains are compared as text. A message from a subdomain of a partner, such as `mail.insurance-partner.com`, is not marked.
* The badge follows the senders of the message or the conversation. In the *Sent* folder, the row lists the recipients. The badge shows there only when a partner wrote a message of the conversation.
* The standard row shortens a list of more than three names and gives the row a label for screen readers. The component of the example does not, so it shows every name.
* The slot of the folder list passes nothing, so the group shows in Mail, Calendar, Contacts and Briefcase. To show it in one vertical only, read the address of the page, as xref:build-by-goal/recipe-tab-and-route.adoc#read-the-vertical-name[Read the vertical name] describes.
* The folder list draws nothing while it has no folders to show, and so no group either.
* The slots show the content of every handler. The badge or the group of another Zimlet shows beside yours.
* The domains and the addresses in `constants/index.js` are placeholders. Replace them with your partners.

. Run the Zimlet with `npm start` and load it in the sideloader, as xref:run-package-deploy/run-and-debug.adoc#load-with-the-sideloader[Run and debug] describes. Wait for the status *Running*, and reload the Modern UI page if the Zimlet was loaded before.

[#expected-result]
== Expected result

* Rows from a partner domain show a *Partner* badge beside the sender names, and no other row changes.
* The folder list has a *Partners* group that opens and closes, with one link for each partner.
* A link opens the page of the partner in a new tab.

[#if-it-did-not-work]
== If it didn't work

No badge shows.::
* Cause: The Zimlet is not loaded, the handler is registered under another key, or the sender is not on the list. The Modern UI does not check keys, so a misspelled key adds nothing and shows no error.
* Fix: Check that the sideloader shows *Running*. Check that the key is `slot::mail-sender` and that you register in `init()`. Check the domain in `constants/index.js` against the address of the sender.

The names of every row are gone.::
* Cause: The handler returns the component for every message and not only for partners, or it returns a component that draws no names.
* Fix: Return `null` when `findPartner` finds nothing, and draw `emailAddresses` in the component.

No *Partners* group shows.::
* Cause: The key is not `slot::folder-group`, or the folder list has no folders to show yet.
* Fix: Check the key and that you register in `init()`. Reload the page and open a screen that has folders.

The heading of the group is empty.::
* Cause: The `name` prop holds a key that the dictionary does not have, or the component is not wrapped with `withIntl`.
* Fix: Use the key `my-zimlet.partners`, merge the texts as the set up describes, and keep `withIntl()` around the component.
