= Add a tab and a screen

This recipe gives your xref:reference/glossary.adoc#zimlet[Zimlet] a tab in the xref:reference/glossary.adoc#modern-ui[Modern UI] and a screen of your own that the tab opens. The example adds a *Meeting rooms* tab to the Video xref:reference/glossary.adoc#vertical[vertical]. The screen lists the rooms of a company meeting service, and each room opens in a new browser tab. The start page of the Video vertical gets a line that points to the tab. Use it when your feature needs a whole screen, such as a list or a form. A small addition to an existing screen needs a slot instead.

[#what-you-will-learn]
== What you will learn

* Choose the vertical and the tab slot (`slot::<vertical>-tab-item`).
* Add a tab with `MenuItem`.
* Add a screen and open it with a route (`slot::routes`).
* Add a line to the standard start page of a vertical (`slot::<vertical>-landing-page-description`).
* Share one address with `useClientConfig`.
* Make the screen work on a narrow window.

[#choose-the-slot]
== Choose the slot

The slot of a tab decides the vertical that shows it, so choose the vertical first. The Modern UI groups its screens into verticals, which the top navigation lists. The first part of a screen's address names its vertical, such as `/videoapps/meeting-rooms`. A vertical shows the tabs of the screens in it. Some verticals depend on the account, and the others exist only when a Zimlet fills one of their slots.

[cols="2,2,4,3",options="header"]
|===
|Vertical |Name in the address |The vertical exists when |Slot for your tab

|Mail
|`email`
|The account has the mail feature.
|`slot::email-tab-item`

|Calendar
|`calendar`
|The account has the calendar feature.
|`slot::calendar-tab-item`

|Contacts
|`contacts`
|The account has the contacts feature.
|`slot::contacts-tab-item`

|Briefcase
|`briefcase`
|The account has the Briefcase feature.
|`slot::briefcase-tab-item`

|Video
|`videoapps`
|An enabled Zimlet registers a handler that adds the vertical.
|`slot::videoapps-tab-item`

|Chat
|`chatapps`
|An enabled Zimlet registers a handler that adds the vertical.
|`slot::chatapps-tab-item`

|Cloud Storage
|`cloudapps`
|An enabled Zimlet registers a handler that adds the vertical.
|`slot::cloudapps-tab-item`

|Integrations
|`integrations`
|An enabled Zimlet registers a handler that adds the vertical.
|`slot::integrations-tab-item`
|===

A handler for the tab slot of Video, Chat, Cloud Storage or Integrations adds that vertical. The first three verticals are also added by a handler for their landing page slot, such as `slot::videoapps-landing-page`. Integrations is also added by a handler for `slot::menu`. A handler from any Zimlet counts, so your Zimlet does not need another Zimlet to add the vertical. When several Zimlets add the same vertical, they share it, and it goes away only when none of them is enabled.

The names in the address are the defaults. The Modern UI reads them from its client configuration, so a deployment can use other names. Read them at run time, as <<read-the-vertical-name,Read the vertical name>> shows.

Choose the vertical by what the screen is for:

* Put a screen that belongs to mail, calendar, contacts or files in that vertical. The tab appears beside the tabs that the vertical already has, and the top navigation does not change.
* Put a screen for a meeting service in Video, for a chat service in Chat, and for a cloud drive in Cloud Storage. The vertical appears in the top navigation for users who have your Zimlet enabled.
* Put anything else in Integrations. The sideloader that loads your Zimlets in development lives there.

The tab shows only while the user is in its vertical. A handler for `slot::videoapps-tab-item` adds nothing to the Mail vertical. See xref:reference/slots/app-shell/navigation-and-tabs.adoc[Navigation and tabs] for the slots of a vertical and for the default page of a vertical that a Zimlet adds. The xref:reference/slots.adoc[slot index] lists every other slot.

[#the-slots]
=== The slots

`slot::videoapps-tab-item`::
The tab slot of the Video vertical, which the example uses for its meeting rooms screen. To use another vertical, change the slot name and the vertical name in `useMeetingsPath`.

`slot::videoapps-landing-page-description`::
The list on the standard start page of the Video vertical, under its introduction. The slot sits in a bulleted list, so the handler returns a list item. The slot does not add the vertical, which the tab slot does. See xref:reference/slots/app-shell/navigation-and-tabs.adoc#vertical-landing-page-description[Navigation and tabs] for the slot.

[#other-slots]
=== Other slots

`slot::videoapps-landing-page`::
The whole start page of the vertical. Choose it when your Zimlet owns the vertical and needs a page of its own, and not a line in the standard one.

`slot::videoapps-landing-page-videos`::
The second column of the standard start page, beside the list. Choose it for demo videos or other media.

[#menu-item]
=== The MenuItem component

`MenuItem` draws one entry of a menu or tab bar in the style of the Modern UI. Choose it for a tab. For an item in an action menu, use `ActionMenuItem`, as xref:build-by-goal/recipe-gear-and-settings-menu.adoc[Add menu items to the app] shows.

*Without it:* a plain link in the tab slot, such as `<a href="/videoapps/meeting-rooms">`, opens the screen. It has none of what `MenuItem` adds: the styling of the other tabs, an icon, and the selected state while its screen is open. The tab looks different from its neighbours and does not show that its screen is open.

*With it:* render the tab as a `MenuItem`.

[source,js]
----
<MenuItem icon={VideoIcon} href={path}>
----

The example uses three of its props:

`href`::
The address to open. The tab shows as selected while the address of the page matches it.

`icon`::
A component from `lucide-preact`, such as `VideoIcon`. Pass the component, not a name.

Children::
The label of the tab, a `<Text>` from `en_US.json`.

Look up every prop of `MenuItem` in xref:reference/shims/components/menus.adoc#menu-item[Menus].

[#mobile-toolbar-and-sidebar]
=== The toolbar and sidebar components

`GenericMobileUIToolbar` and `GenericMobileUISidebar` come from `@zimbra-client/components`.

*Without them:* the Modern UI shows the screen of a route as it is and adds nothing around it. In a narrow window the screen then has no toolbar and no sidebar button. It does not offer the sidebar that lists the tabs of the vertical.

*With them:* render both at the top of the screen.

[source,js]
----
<GenericMobileUIToolbar />
<GenericMobileUISidebar />
----

In a narrow window they show a toolbar with the name of the vertical. A button on it opens a sidebar that lists the tabs of the vertical, including yours. In a wide window they add nothing that you can see. See xref:reference/shims/components/layout.adoc[Layout] for both.

[#if-it-did-not-work]
== If it didn't work

The *Video* vertical is not in the top navigation.::
* Cause: The Zimlet is not loaded, or the handler is registered under another key. The Modern UI does not check keys, so a misspelled key adds nothing and shows no error.
* Fix: Check that the sideloader shows the Zimlet as *Running*. Check that the key is `slot::videoapps-tab-item` and that you register it in `init()`. Reload the page, because the verticals are set up once the Zimlets have loaded. Add `?zimletSlots=show` to the address to see the slot labels, as xref:run-package-deploy/run-and-debug.adoc#debug-slots[Run and debug] describes.

The start page has no line.::
* Cause: The handler is registered under another key. The Modern UI does not check keys, so a misspelled key adds nothing and shows no error.
* Fix: Check that the key is `slot::videoapps-landing-page-description`, that you register in `init()` and that the handler returns a list item. See xref:reference/slots/app-shell/navigation-and-tabs.adoc#vertical-landing-page-description[Navigation and tabs] for when the slot draws nothing.

The vertical is there, but the tab is not.::
* Cause: A tab shows only while the user is in its vertical. A handler for the tab slot of another vertical adds nothing here.
* Fix: Choose the vertical that the slot name names. For `slot::videoapps-tab-item`, that is *Video*.

The tab opens a page that reads *Not Found*.::
* Cause: No route matches the address of the tab, because the address of the tab differs from the `path` of the route.
* Fix: Build both addresses with `useMeetingsPath`, as the example does, and do not type the address in one of them.

The screen shows no toolbar and no sidebar button in a narrow window.::
* Cause: The screen does not render `GenericMobileUIToolbar` and `GenericMobileUISidebar`.
* Fix: Render both at the top of the screen, as the example does.

A *Join* link opens a page that does not load.::
* Cause: The example rooms use placeholder addresses.
* Fix: Replace the addresses in `ROOMS` with the rooms of your own service.
