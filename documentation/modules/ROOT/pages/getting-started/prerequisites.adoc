= What you need before you start

Before you build a Zimlet, you need a Zimbra server that runs the xref:reference/glossary.adoc#modern-ui[Modern UI] and working knowledge of a few web technologies. This page tells you what the server must provide and how much of each technology you need. The guide does not teach those technologies. It links to their official documentation. Use it as a checklist of what to arrange before you install anything.

[#zimbra-server]
== Get a Zimbra server

You need a Zimbra server that runs the Modern UI. It can be a test server or a production server. There is no stand-alone or hosted environment for partners who have no server.

The server must provide:

* An account that can sign in to the Modern UI. Any valid account works, so a test account is not required.
* The xref:run-package-deploy/run-and-debug.adoc[sideloader] Zimlet, installed and enabled for that account. It loads the Zimlet that runs on your machine into the Modern UI.
* A Modern UI version number that you can read. See xref:getting-started/prerequisites.adoc#find-modern-ui-version[Find the Modern UI version].
* A way to deploy a Zimlet: access to the Admin Console or a shell on the server, or an administrator who deploys for you.

You install the sideloader in xref:getting-started/setup-environment.adoc[Set up your machine].

[#find-modern-ui-version]
== Find the Modern UI version

The Modern UI version tells you which xref:reference/glossary.adoc#semver-range[semver range] to package your Zimlet with.

1. Sign in to the Modern UI.
2. Click the settings icon (the gear) in the top right.
3. Choose *About*.
4. Read the number on the `Zimbra Modern Web App Version` line. Ignore the server version below it.

The `Zimbra Modern Web App Version` line shows the version number, then a build identifier and a build date. The server version is on the next line.

.The About dialog of the Modern UI
image::prerequisites-about-dialog.png["The About dialog. The first line, Zimbra Modern Web App Version, gives the Modern UI version, for example 4.50.0. The server version is on the line below it."]

The `--zimbraXVersion` option of `zimlet package` takes the semver range. The option is optional. Without it, the range is `>=1.0.0`, which accepts every Modern UI version. Set a range to keep your Zimlet off versions you have not tested.

[#technologies]
== Know the technologies

Learn any technology that is new to you from its official documentation. The sections below group the technologies by how much the guide needs them.

=== Required

You cannot develop a Zimlet without these.

JavaScript::
You write the Zimlet in JavaScript, with ES modules and promises. Aim for working knowledge. Read the https://developer.mozilla.org/en-US/docs/Web/JavaScript[JavaScript guide on MDN^].

Node.js 24 and npm::
They run the `zimlet` tool and install your dependencies. The tool needs Node.js 24.18.0 or later and npm 11. Node.js 24 includes npm 11. The Node.js version affects only your build, not how the Zimlet runs in the Modern UI. A Zimlet built with an older version can still work, but that setup is unsupported. Aim for running commands and reading their output. Read the https://nodejs.org/en/download[Node.js downloads^] and the https://docs.npmjs.com/[npm documentation^].

A code editor::
You edit JavaScript, JSX, Less and JSON files. Any editor works. Read the https://code.visualstudio.com/docs[Visual Studio Code documentation^] if you use it.

Shell basics::
You run the commands in a POSIX shell. On the server, an administrator deploys from a shell. Aim for changing folders and running commands. Read the https://pubs.opengroup.org/onlinepubs/9699919799/utilities/V3_chap02.html[POSIX shell command language^].

HTTPS and self-signed certificates::
The Zimlet development server uses HTTPS with a self-signed certificate. Your browser blocks it until you accept it. Aim for awareness of what it is and how to accept it. Read the https://developer.mozilla.org/en-US/docs/Web/Security/Transport_Layer_Security[Transport Layer Security on MDN^].

=== Recommended

The guide assumes these, and you can work without them.

Preact and JSX::
You build the user interface of a Zimlet with Preact components written in JSX. Aim for working knowledge of components, props and hooks. Read the https://preactjs.com/guide/v10/getting-started[Preact guide^].

Semver ranges::
You package a Zimlet with a range of Modern UI versions, such as `^4.42.0`. Aim for reading a range. Read the https://semver.org/[Semantic Versioning^] and the https://github.com/npm/node-semver#ranges[range syntax of node-semver^].

=== When needed

You need these only for the feature named in each entry.

CSS::
You style the user interface of a Zimlet with CSS. See xref:go-deeper/styling.adoc[Styling]. Aim for working knowledge. Read the https://developer.mozilla.org/en-US/docs/Web/CSS[CSS on MDN^].

`preact-router`::
A Zimlet that adds a screen registers a route. See xref:build-by-goal/recipe-tab-and-route.adoc[Add a tab and a screen]. Use the router of the Modern UI. Aim for basic knowledge. Read the https://github.com/preactjs/preact-router[preact-router documentation^].

Redux::
You read or change state that the Modern UI shares. See xref:go-deeper/redux.adoc[Shared state with Redux]. The Modern UI provides `react-redux` and `redux-actions` to your Zimlet. Aim for basic knowledge. Read the https://redux.js.org/[Redux documentation^] and the https://react-redux.js.org/[React Redux documentation^].

=== Optional

These help, and no step in the guide depends on them.

Git::
It keeps the history of your Zimlet. The `zimlet` tool does not need it. Aim for basic knowledge. Read the https://git-scm.com/doc[Git documentation^].

Less::
The `zimlet` tool compiles Less files, and plain CSS works as well. Aim for basic knowledge. Read the https://lesscss.org/[Less documentation^].

CSS Modules::
Style files in the `components`, `screens` and `pages` folders of `src` are CSS Modules. Their class names apply only to the component that imports them. Aim for basic knowledge. Read the https://github.com/css-modules/css-modules[CSS Modules documentation^].

ESLint::
It finds errors in your code before you build. See xref:run-package-deploy/lint-your-code.adoc[Lint]. Aim for basic knowledge. Read the https://eslint.org/docs/latest/[ESLint documentation^].
