= Your first Zimlet

This tutorial takes you from an empty folder to a working Zimlet. You create it from the default template and run it in the xref:reference/glossary.adoc#modern-ui[Modern UI]. You see how it adds a tab and a page, change the page and package it for deployment. It is the first hands-on step after setup, and it shows the whole development loop that every later Zimlet follows.

== Before you start

Complete the ready check in xref:getting-started/setup-environment.adoc#ready-check[Set up your machine]. You need Node.js 24, the `zimlet` tool and the xref:run-package-deploy/run-and-debug.adoc#load-with-the-sideloader[sideloader] on your Zimbra server. Run the commands in a folder where you keep your projects.

[#create-from-template]
== Create a Zimlet from the template

The default template is a small working Zimlet. It adds a tab to the Mail section that opens a page with the text "Hello World".

. Create the Zimlet and go into its folder:
+
[source,sh]
----
zimlet create default my-zimlet
cd my-zimlet
----

The command downloads the template, copies it into a new `my-zimlet` folder and installs the dependencies. It ends with `Done!`. The name becomes the package name, the label of the tab and part of the page address. Use lowercase letters, digits and hyphens, and give a name, not a path.

The new folder holds the files you work with:

* `src/index.js` is the entry file. It adds the tab and the page to the Modern UI.
* `src/components/` holds the tab and the page.
* `src/intl/en_US.json` holds the Zimlet label, its description and the English texts.
* `package.json` holds the scripts that you run in the next steps.

See xref:fundamentals/project-structure.adoc[Project structure] for every file and field.

[#run-with-npm-start]
== Run it with npm start

The development server builds your Zimlet and serves it from your machine, so the Modern UI can load it.

. Start the development server:
+
[source,sh]
----
npm start
----
. Wait for the line `Compiled successfully!`.
. Accept the server's certificate in your browser the first time. Follow xref:getting-started/setup-environment.adoc#accept-certificate[Accept the development HTTPS certificate].

The output ends with the addresses of the server:

[source,text]
----
Compiled successfully!

You can view the application in browser.

Local:            http://localhost:8081/index.js
On Your Network:  http://<your-ip-address>:8081/index.js
----

Keep this terminal open while you work. The server listens on port 8081 and answers only over HTTPS, so use `https://localhost:8081/index.js` even though the output shows `http://`.

[#load-with-sideloader]
== Load it through the sideloader

The xref:run-package-deploy/run-and-debug.adoc#load-with-the-sideloader[sideloader] loads the Zimlet from your development server into the Modern UI. Keep the development server from the previous section running. Your browser must have accepted its certificate.

. Sign in to the Modern UI.
. Choose *Integrations*, then choose the *Zimlets Sideloader* tab.
. In the Zimlet Name field, enter `my-zimlet`.
. Keep the address `https://localhost:8081/index.js` in the address field.
. Choose *Load Zimlet*.
. In Chrome, a prompt can ask to access other apps and services on this device. Choose *Allow*. See xref:getting-started/setup-environment.adoc#allow-chrome-access[Allow Chrome to reach your development server].

The *Zimlets Loaded By Sideloader* table lists `my-zimlet` with the status *Running*. *Persist on Reload* is ticked, so the sideloader loads the Zimlet again on every page reload. See xref:run-package-deploy/run-and-debug.adoc#persist[Keep the Zimlet loaded with Persist on Reload] for how that works.

[#how-it-works]
== How the tab and the page get on the screen

The template adds the tab and the page with two handlers. A xref:fundamentals/extending-the-ui.adoc[slot] is a named place in a screen of the Modern UI. A handler is a function that you register for a slot, and the slot shows what the handler returns. `plugins` is a field of the xref:fundamentals/host-context.adoc[context] that the Modern UI passes to your Zimlet. `src/index.js` registers both handlers in xref:fundamentals/factory-and-lifecycle.adoc#init[`init()`]:

[source,js]
----
plugins.register('slot::email-tab-item', EmailTabItem);
plugins.register('slot::routes', EmailTabRoute);
----

xref:reference/slots/app-shell/navigation-and-tabs.adoc#vertical-tab-item[`slot::email-tab-item`]::
The tab bar of Mail. The handler returns the *my-zimlet* tab, the component in `src/components/EmailTabItem/`.

xref:reference/slots/app-shell/app-frame.adoc#routes[`slot::routes`]::
The screens that open at an address. The handler returns the page for the address that the tab links to, the component in `src/components/app/`.

The tab links to an address, and the page is registered for the same address, so choosing the tab opens the page. The Modern UI calls `init()` once after it loads the Zimlet, which is why the handlers are registered there. See xref:fundamentals/factory-and-lifecycle.adoc[Factory and lifecycle] for the entry file and xref:fundamentals/extending-the-ui.adoc[Slots and handlers] for how a slot calls its handlers. To build a tab of your own, follow xref:build-by-goal/recipe-tab-and-route.adoc[Add a tab and a screen].

[#build-and-package]
== Build and package

Stop the development server with `Ctrl+C`. In the sideloader, clear *Persist on Reload* for `my-zimlet`, as xref:run-package-deploy/run-and-debug.adoc#persist[Run and debug] explains.

. Build the Zimlet:
+
[source,sh]
----
npm run build
----
. Package it:
+
[source,sh]
----
npm run package
----

The build prints `Compiled successfully!` and writes the Zimlet to `build/index.js`. The package command prints the path of the zip:

[source,text]
----
Successfully packaged zimlet to: <your-project-path>/my-zimlet/pkg/my-zimlet.zip
----

The zip holds `index.js`, `index.js.LICENSE.txt`, a `my-zimlet.xml` xref:run-package-deploy/build-and-package.adoc[descriptor] and a `my-zimlet.properties` file. The descriptor carries the label and description from `src/intl/en_US.json`.

The `package` script in `package.json` packages the Zimlet for Modern UI versions `^{modern-ui-version}`. Change that range to match your server. See xref:getting-started/prerequisites.adoc#find-modern-ui-version[Find the Modern UI version]. For every option of these commands, see xref:run-package-deploy/build-and-package.adoc[Build and package].

== Expected result

* The Modern UI shows a *my-zimlet* tab that opens a page with your new line below "Hello World".
* The `build` folder holds `index.js`.
* The `pkg` folder holds `my-zimlet.zip`, ready to deploy as xref:run-package-deploy/deploy.adoc[Deploy] describes.

[#if-it-did-not-work]
== If it didn't work

`zimlet create` prints `Invalid package name`.::
* Cause: The name is a path, such as `./my-zimlet`, or contains characters that a package name cannot have.
* Fix: Run the command in the folder where the project goes, and give only the name: `zimlet create default my-zimlet`.

`npm start` stops with `Error: listen EADDRINUSE`.::
* Cause: Another program, such as a second development server, uses port 8081. The tool normally moves to the next free port, but it can miss a program that listens only on `localhost`.
* Fix: Stop that program, or start your Zimlet on another port with `npm start -- --port 8082`. Use the port that the terminal prints in the sideloader address and when you accept the certificate.

The sideloader table shows `undefined` as the name.::
* Cause: You loaded the Zimlet without a name.
* Fix: Clear *Persist on Reload* for that entry and reload the Modern UI page. Then load the Zimlet again with the name `my-zimlet`.

The status shows `Error: TypeError: Failed to fetch` and not *Running*.::
* Cause: The development server is not running, the browser has not accepted its certificate, or Chrome blocked the request to your machine.
* Fix: Check that `npm start` is still running, then accept the certificate as xref:getting-started/setup-environment.adoc#accept-certificate[Accept the development HTTPS certificate] describes. In Chrome, also check that the *Apps on device* permission is on, as xref:getting-started/setup-environment.adoc#allow-chrome-access[Allow Chrome to reach your development server] describes. Then reload the Modern UI page, which loads the Zimlet again.

The page still shows the old text after you save.::
* Cause: The Modern UI does not update a page that is already open.
* Fix: Reload the Modern UI page.
