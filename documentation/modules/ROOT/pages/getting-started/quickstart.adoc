= Your first Zimlet

This tutorial takes you from an empty folder to a working Zimlet. You create it from the default template, run it in the xref:reference/glossary.adoc#modern-ui[Modern UI], change it and package it for deployment. It is the first hands-on step after setup, and it shows the whole development loop that every later Zimlet follows.

== Before you start

Complete the ready check in xref:getting-started/setup-environment.adoc#ready-check[Set up your machine]. You need Node.js 24, the `zimlet` tool and the xref:test-package-deploy/run-and-debug.adoc[sideloader] on your Zimbra server. Run the commands in a folder where you keep your projects.

[#create-from-template]
== Create a Zimlet from the template

The default template is a small working Zimlet. It adds a tab to the Mail section that opens a page with the text "Hello World".

. Create the Zimlet and go into its folder:
+
[source,sh]
----
zimlet create default my-zimlet
cd my-zimlet
----

The command downloads the template, copies it into a new `my-zimlet` folder and installs the dependencies. It ends with `Done!`. The name becomes the package name, the label of the tab and part of the page address. Use lowercase letters, digits and hyphens, and give a name, not a path.

The new folder holds the files you work with:

* `src/index.js` is the entry file. It adds the tab and the page to the Modern UI.
* `src/components/` holds the tab and the page.
* `src/intl/en_US.json` holds the Zimlet label, its description and the English texts.
* `package.json` holds the scripts that you run in the next steps.

See xref:fundamentals/project-structure.adoc[Project structure] for every file and field.

[#run-with-npm-start]
== Run it with npm start

The development server builds your Zimlet and serves it from your machine, so the Modern UI can load it.

. Start the development server:
+
[source,sh]
----
npm start
----
. Wait for the line `Compiled successfully!`.
. Accept the server's certificate in your browser the first time. Follow xref:getting-started/setup-environment.adoc#accept-certificate[Accept the development HTTPS certificate].

The output ends with the addresses of the server:

[source,text]
----
Compiled successfully!

You can view the application in browser.

Local:            http://localhost:8081/index.js
On Your Network:  http://<your-ip-address>:8081/index.js
----

Keep this terminal open while you work. The server listens on port 8081 and answers only over HTTPS, so use `https://localhost:8081/index.js` even though the output shows `http://`.

[#load-with-sideloader]
== Load it through the sideloader

The xref:test-package-deploy/run-and-debug.adoc[sideloader] loads the Zimlet from your development server into the Modern UI.

. Sign in to the Modern UI.
. Choose *Integrations*, then choose the *Zimlets Sideloader* tab. If they are missing, see xref:getting-started/setup-environment.adoc#sideloader[Install and enable the sideloader].
. In the Zimlet Name field, enter `my-zimlet`.
. Keep the address `https://localhost:8081/index.js` in the address field.
. Choose *Load Zimlet*.

The *Zimlets Loaded By Sideloader* table lists `my-zimlet` with the status *Running*. *Persist on Reload* is ticked, so the Modern UI loads the Zimlet again whenever you reload the page.

[#see-and-change]
== See the result and change it

. Choose *Mail*. A *my-zimlet* tab appears next to the *Mail* tab.
. Choose the *my-zimlet* tab. The page shows the text "Hello World".

.The my-zimlet tab and its page in the Modern UI
image::quickstart-hello-world.png["The Mail section with a my-zimlet tab beside the Mail tab. The tab is selected and the page below it shows the text Hello World"]

Now change the text:

. Open `src/intl/en_US.json` in your editor.
. Change the value of `helloWorld`, for example to `Hello from my first Zimlet`, and save the file.
. Check that the terminal prints `Compiled successfully!` again.
. Reload the Modern UI page and open the *my-zimlet* tab again.

The page shows your new text. The page that is already open keeps the old text until you reload it. The page text comes from the translation file, which is why you edit `en_US.json` and not a component.

[#build-and-package]
== Build and package

Stop the development server with `Ctrl+C`. In the sideloader, clear *Persist on Reload* for `my-zimlet`, so the Modern UI does not try to load it again.

. Build the Zimlet:
+
[source,sh]
----
npm run build
----
. Package it:
+
[source,sh]
----
npm run package
----

The build prints `Compiled successfully!` and writes the Zimlet to `build/index.js`. The package command prints the path of the zip:

[source,text]
----
Successfully packaged zimlet to: <your-project-path>/my-zimlet/pkg/my-zimlet.zip
----

The zip holds `index.js`, `index.js.LICENSE.txt`, a `my-zimlet.xml` xref:test-package-deploy/build-and-package.adoc[descriptor] and a `my-zimlet.properties` file. The descriptor carries the label and description from `src/intl/en_US.json`.

The `package` script in `package.json` packages the Zimlet for Modern UI versions `^4.0.0`. Change that range to match your server. See xref:getting-started/prerequisites.adoc#find-modern-ui-version[Find the Modern UI version]. For every option of these commands, see xref:test-package-deploy/build-and-package.adoc[Build and package].

== Expected result

* The Modern UI shows a *my-zimlet* tab that opens a page with your text.
* The `build` folder holds `index.js`.
* The `pkg` folder holds `my-zimlet.zip`, ready to deploy as xref:test-package-deploy/deploy.adoc[Deploy] describes.

[#if-it-did-not-work]
== If it didn't work

`zimlet create` prints `Invalid package name`.::
* Cause: The name is a path, such as `./my-zimlet`, or contains characters that a package name cannot have.
* Fix: Run the command in the folder where the project goes, and give only the name: `zimlet create default my-zimlet`.

`npm start` stops with `Error: listen EADDRINUSE`.::
* Cause: Another program, such as a second development server, uses port 8081.
* Fix: Stop that program, or start your Zimlet on another port with `npm start -- --port 8082`. Use the same port in the sideloader address and when you accept the certificate.

The sideloader table shows `undefined` as the name.::
* Cause: You loaded the Zimlet without a name.
* Fix: Clear *Persist on Reload* for that entry and reload the Modern UI page. Then load the Zimlet again with the name `my-zimlet`.

The status shows `Error: TypeError: Failed to fetch` and not *Running*.::
* Cause: The development server is not running, or the browser has not accepted its certificate.
* Fix: Check that `npm start` is still running, then accept the certificate as xref:getting-started/setup-environment.adoc#accept-certificate[Accept the development HTTPS certificate] describes. Then reload the Modern UI page, which loads the Zimlet again.

The page still shows the old text after you save.::
* Cause: The Modern UI does not update a page that is already open.
* Fix: Reload the Modern UI page.
