= Classic and Modern Zimlets

A Classic Zimlet extends the Classic UI, the older Zimbra web client. A Modern Zimlet is a xref:reference/glossary.adoc#zimlet[Zimlet] that extends the xref:reference/glossary.adoc#modern-ui[Modern UI] and is built in a different way. Compare how each kind runs and is packaged. See which Classic use cases the Modern UI covers, and which only a Classic Zimlet can do, with a workaround or alternative for each. Use it when you maintain Classic Zimlets and plan Modern versions, or to check whether a Modern Zimlet can do what a Classic Zimlet does. The two kinds share no code and no package, so you write a new Modern Zimlet for each Classic Zimlet that you want to offer.

[#differences]
== Differences

The table compares how each kind of Zimlet runs, extends the UI and is packaged.

[cols="1,2,2",options="header"]
|===
| Topic | Classic Zimlet | Modern Zimlet

| Where the code runs
| In the page of the Classic UI, with its global objects such as `appCtxt`.
| In its own scope inside the Modern UI, with its own globals. It receives the xref:fundamentals/host-context.adoc[context] from the Modern UI.

| Entry point
| A handler object that the descriptor names with `<handlerObject>`. It extends `ZmZimletBase` and has an `init()` method.
| A default exported xref:fundamentals/factory-and-lifecycle.adoc[factory] that returns an object with an `init()` method.

| How it extends the UI
| Descriptor elements and handler methods that the Classic UI calls, such as `onMsgView`.
| Handlers that `init()` registers for xref:fundamentals/extending-the-ui.adoc[slots] and for other keys.

| Screen elements
| Classic UI classes such as `DwtDialog`.
| Preact components, including the xref:reference/shims/blocks.adoc[Blocks UI kit].

| Descriptor
| Written by hand. It names the handler and the files. It can also describe a panel item, a content object, user properties and a server extension.
| Generated by `zimlet package`. It lists the files, the label, the version and the version range. See xref:run-package-deploy/build-and-package.adoc#descriptor[The descriptor and the properties files].

| Texts
| `.properties` files that the handler reads with `getMessage`.
| JSON files in the `intl` folder. See xref:go-deeper/localization.adoc[Localization].

| Compatibility
| No version range. The server gives the Zimlet to the Classic UI only.
| A version range in `zimbraXZimletCompatibleSemVer`. The server gives the Zimlet to the Modern UI only when the range includes its version.
|===

The server keeps the two kinds apart. A request from the Classic UI gets only the Zimlets that have no version range. A request from the Modern UI gets only the Zimlets whose range includes its version. A package of one kind is therefore never loaded by the other client.

The Modern UI does not run Classic Zimlet code, and it has no Classic objects such as `appCtxt` or `ZmZimletBase`.

[#covered]
== Use cases that the Modern UI covers

The Classic UI calls a Zimlet through named hooks, and it has more than a hundred. The tables group them by use case and name the main hook of each. A Modern Zimlet reaches the same result in a different way.

[cols="2,3",options="header"]
|===
| Classic use case | Modern UI

| Run code when the Zimlet loads (`init`)
| The `init()` method of the xref:fundamentals/factory-and-lifecycle.adoc[factory].

| Add toolbar buttons and menu items (`initializeToolbar`, `onActionMenuInitialized`, `onDraftsActionMenuInitialized`, `onBriefcaseActionMenuInitialized`)
| Menu slots such as `action-menu-mail-more`. See xref:reference/slots/mail/mail-menus-and-actions.adoc[Mail menus and actions], xref:reference/slots/contacts.adoc[Contacts] and xref:reference/slots/briefcase.adoc[Briefcase].

| Show content when a message or a contact opens (`onMsgView`, `onMsgExpansion`, `onContactView`)
| Slots such as `message-body-top` and `contact-card-item`. See xref:reference/slots/mail/message-viewer.adoc[Message viewer] and xref:reference/slots/contacts.adoc[Contacts].

| Find text in a message and make it clickable (`onFindMsgObjects`, `contentObject`, `match`, `clicked`)
| Content processors such as `messageProcessors:emailProcessor` change the message before it shows, for example to turn matched text into links. The code that finds the text is your own. See xref:reference/slots/content-processors.adoc[Content processors].

| Show a card when the user points at an address (`onEmailHover`, `onHoverOverEmailInList`)
| The `contact-hover-card-details` slot. See xref:reference/slots/contacts.adoc[Contacts].

| Check a message before it is sent (`emailErrorCheck`, `onSendButtonClicked`)
| The `ONBEFORESEND` event. Reject the promise of your listener to stop the send. See xref:go-deeper/app-events.adoc[App events].

| Know that a message was sent (`onSendMsgSuccess`)
| The `AFTERONSEND` event. See xref:go-deeper/app-events.adoc[App events].

| Add controls to the composer (`initializeAttachPopup`, `onZmComposeView_getIdentityOptions`)
| Slots such as `composer-toolbar-end`, `compose-attachment-action-menu` and `from-options`. See xref:reference/slots/composer/mail-composer.adoc[Mail composer].

| Add an action or a field to an event (`onZmApptController_createToolBar`, `onZmCalViewController_getActionMenuOps`)
| Slots such as `action-menu-event-context-menu` and `calendar-appointment-edit-location`. See xref:reference/slots/calendar/events-and-appointments.adoc[Events and appointments].

| Know when an event is saved, deleted or dropped on a new time (`onSaveApptSuccess`, `onAppointmentDelete`, `onApptDrop`)
| The `appointmentMonitor` prop of the `calendar-body-end` slot. See xref:reference/slots/calendar/calendar-view.adoc[Calendar view].

| Subscribe to an external calendar (`onZmExternalCalendarDialog_popup`)
| The calendar subscription slots. See xref:reference/slots/calendar/calendar-view.adoc[Calendar view].

| Let users change options and save them (`userProperties`, `createPropertyEditor`, `onZmPreferencesApp_registerPrefs`, `saveUserProperties`)
| The `settings` key adds a section to the Settings dialog. See xref:reference/slots/settings.adoc[Settings].

| Read values that an administrator sets (`getConfig`)
| The `config_template.xml` file, read with `useAccountInfo`. See xref:go-deeper/server-data/zimlet-configuration.adoc[Zimlet configuration].

| Store data in the mailbox (`ZmMetaData`)
| xref:go-deeper/server-data/metadata.adoc[Mailbox metadata].

| Read account settings (`appCtxt.get`)
| Hooks such as `useAccountInfo`. See xref:reference/shims/hooks/account-and-preferences.adoc[Account and preferences].

| Show a status or error message, or a dialog (`displayStatusMessage`, `displayErrorMessage`, `makeCanvas`)
| The `notify` action and the dialogs of the Blocks UI kit. See xref:reference/context/store/zimlet-redux/actions.adoc#notify[`notify`] and xref:reference/shims/blocks/dialogs-and-overlays.adoc[Dialogs and overlays].

| Add an application screen (`createApp`)
| A tab and a route. See xref:reference/slots/app-shell/navigation-and-tabs.adoc[Navigation and tabs].

| Add a button to the search bar (`addSearchDomainItem`)
| The `web-search-toggle` slot. See xref:reference/slots/app-shell/search.adoc[Search].
|===

[#not-supported]
== Use cases that only a Classic Zimlet can do

A Classic Zimlet can implement each use case below, and the Modern UI offers no extension point for it. The last column gives a workaround or the closest alternative. *None found* means that the Modern UI offers neither.

[cols="2,2,3",options="header"]
|===
| Use case | Classic hooks | Workaround or alternative

| Know when a mail item is flagged or tagged
| `onMailFlagClick`, `onTagAction`
| None found. The Modern UI sends only the xref:go-deeper/app-events.adoc[app events].

| Run code when a search runs, or add results
| `onSearch`, `onPeopleSearchData`, `onPeopleSearchShow`, `onZmSearchResultsController_displayResults1`
| Build your own search field in the `web-search` slot, and read the query from it. The slot replaces the search field for every user of the Zimlet. See xref:reference/slots/app-shell/search.adoc[Search] and xref:build-by-goal/recipe-search-bar.adoc[Extend the search bar].

| Change the content of a row in the message list
| `onZmConvListView_getAbridgedContent`, `onZmMailMsgListView_getAbridgedContent`, `onZmMailMsg_addFrom1`
| Replace the sender names of a row with the `mail-sender` slot. For the rest of the row, none found. See xref:reference/slots/mail/mail-list-and-sidebar.adoc[Mail list and sidebar].

| Add an item to the menu of an address
| `onParticipantActionMenuInitialized`, `onBubbleActionMenu`
| Add a link or a fact to the card that opens from the address with `contact-hover-card-details`. See xref:reference/slots/contacts.adoc[Contacts].

| Change the outgoing message while it is sent
| `appendExtraSignature`, `addExtraMsgParts`, `addCustomMimeHeaders`, `onZmComposeController_sendMsg`
| Send the message yourself from an `ONSEND` listener, as a Zimlet that signs or encrypts does. See xref:go-deeper/app-events.adoc[App events].

| Know that a message failed to send, or that the composer closed
| `onSendMsgFailure`, `onDisposeComposeController`
| None found. `AFTERONSEND` runs only after a message was sent.

| Change how the composer builds its form
| `onZmComposeView_createHtmlFromTemplate`, `onZmComposeView_set`, `onZmComposeView_getIdentity`
| Add content with the composer slots, or hide a control with the xref:reference/slots/hide-built-in-ui.adoc[hide slots]. See xref:reference/slots/composer/mail-composer.adoc[Mail composer].

| Edit a contact in the contact form
| `onContactEdit`, `onZmContactSplitView_showContactListItem`
| Show your own data in the contact details with `contact-card-item`. The edit form has no extension point.

| Add a button to an invitation in a message
| `onZmInviteMsgView_createInviteToolbar`, `onZmInviteMsgView_enableToolbarButtons`
| React to the answer of the user with the `ONSENDINVITEREPLY` event. See xref:go-deeper/app-events.adoc[App events].

| React when the user edits an event, or when saving fails
| `onEditAppt_updateAttendees`, `onEditAppt_updateTime`, `onZmApptEditView_show`, `onSaveApptFailure`
| Use the `attendees-chooser-attendees` slot for code that reacts when the user changes the event. The `before` events of `appointmentMonitor` run before the save. For a failed save, none found. See xref:reference/slots/calendar/events-and-appointments.adoc[Events and appointments].

| Change how the calendar draws its days, titles and lists
| `onZmCalColView_createHoursHtml`, `onZmCalListView_updateTitle`, `onZmApptListView_getCellId`
| None found. The `calendar-body-end` slot adds content after the calendar and does not change it.

| Check or change the built-in preferences when the user saves them
| `onZmPref_validateEmail`, `onZmPrefController_saveListener`, `onZmPreferencesPage_setupCheckbox`, `onZmSignaturesPage_resetUsageSelects`, `onZmSettings_setUserSettings`
| Add your own section with the `settings` key, add a control to a built-in page with a page slot, or hide a built-in control. To check a built-in value, none found. See xref:reference/slots/settings.adoc[Settings].

| Change a built-in dialog, such as folder properties, the folder chooser, import and export, or the filter rules
| `onZmFolderPropsDialog_handleFolderChange`, `onZmAppCtxt_getChooseFolderDialog1`, `onZmImportExportBaseView_folderButton_onclick`, `onZmFilterRuleDialog_popup`
| Only some dialogs have slots: `filter-options` and `additional-filter-settings` for the filters, and `change-password-description` for text in the *Change Password* dialog. For the other dialogs, none found. See xref:reference/slots/settings.adoc[Settings] and xref:reference/slots/app-shell/header-menus.adoc[Header menus].

| Enable, disable or reorder the built-in toolbar and menu items
| `resetToolbarOperations`, `onMailActionMenuResetOperations`, `onZmOperation_initialize`, `onZmMailApp_registerOperations`
| Hide an item with the xref:reference/slots/hide-built-in-ui.adoc[hide slots], and add your own items with the menu slots. Enabling, disabling or reordering: none found.

| React when the user changes the app or the screen, or choose the start app
| `onSelectApp`, `onAction`, `runAppFunction`, `onShowView`, `onZmZimbraMail_getDefaultStartAppName`
| None found for the built-in screens.

| Change the text of a desktop notification
| `onZmDesktopAlert_getDisplayText`
| None found.

| Add an item to the Zimlets panel, with a click, a double click, a menu and a tooltip
| `zimletPanelItem`, `singleClicked`, `doubleClicked`, `getActionMenu`
| The Modern UI has no Zimlets panel. Put the control in the app instead. Use a header menu, the strip or the panel at the right edge, or the area below the folder list. See xref:build-by-goal/recipe-sidebar-widget.adoc[Add a sidebar widget] and xref:build-by-goal/recipe-gear-and-settings-menu.adoc[Add menu items to the app].

| Drag items onto a Zimlet, or drag from it
| `dragSource`, `doDrag`, `doDrop`, `onApptDrag`
| None found.

| Show a portlet
| `portlet`, `portletCreated`, `portletRefreshed`
| The closest alternative is a panel that stays in view, from the `rightside-zimlet-slot` slot. See xref:reference/slots/app-shell/app-frame.adoc[App frame].

| Show a tooltip or a menu on matched text in a message
| `toolTipPoppedUp`, `hoverOver`, `contentObject` with `contextMenu`
| Turn the matched text into a link with a content processor. For a tooltip or a menu, none found. See xref:reference/slots/content-processors.adoc[Content processors].

| Call an outside service through the Zimbra proxy
| `sendRequest`
| Call the proxy of the server with `fetch`, as xref:go-deeper/server-data/fetch.adoc[Call a server API with fetch] describes, at `/service/proxy?target=<outside-address>`. An administrator must list the domain of the service in the `zimbraProxyAllowedDomains` attribute of the class of service.

| Ship a Java server extension with the Zimlet
| `serverExtension`
| The descriptor that `zimlet package` writes has no element for it. Provide the extension on its own and call its endpoint with `fetch`. See xref:go-deeper/server-data/fetch.adoc#other-endpoints[Other endpoints].

| Use Classic UI classes and globals
| `appCtxt`, `Dwt`, `Zm` and `Ajx` classes
| Not supported. Use the xref:fundamentals/host-context.adoc[context] and the xref:reference/shims/blocks.adoc[Blocks UI kit] instead.
|===

[#not-confirmed]
== Not confirmed

Admin Console Zimlets::
Zimlets that extend the Admin Console, such as the admin chat and mail recall Zimlets, use Admin Console classes. The Modern UI has no extension point for the Admin Console. Whether another way exists is not confirmed.

Before you plan a Modern Zimlet around a use case that is not covered above, ask in xref:help-and-migration/faq-and-getting-help.adoc[FAQ and getting help].
