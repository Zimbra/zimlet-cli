= Zimlet developer guide

This guide shows you how to extend the Zimbra xref:reference/glossary.adoc#modern-ui[Modern UI] with features of your own. It covers the whole work of a xref:reference/glossary.adoc#zimlet[Zimlet] author, from setting up your development environment, through building and running a Zimlet, to deploying it on a Zimbra server. It is the starting point for new readers, and the <<reading-paths,reading paths>> help you find the pages for your goal.

== What is a Zimlet

A xref:reference/glossary.adoc#zimlet[Zimlet] is an extension of the xref:reference/glossary.adoc#modern-ui[Modern UI], the Zimbra web client. It is a small JavaScript program that the Modern UI loads and runs in the browser. You write it as source files, build and package it into a zip file, and an administrator deploys it to the Zimbra server and enables it for the accounts that use it. From then on, the Modern UI loads it for those accounts.

A Zimlet adds to what the Modern UI already does. It does not replace the Modern UI, and it works inside screens that already exist. A Zimlet can:

* Add content to an existing screen, such as extra content in a message or a menu item.
* Add a section to the settings, or a new screen of its own.
* React to what happens in the Modern UI, such as a message being sent, and do work without showing anything.

Because a Zimlet is a feature of its own, you can build, test and ship it separately from the Modern UI. Users get the feature when it is enabled for their account, and an administrator can disable it again without changing the Modern UI.

See xref:getting-started/concepts.adoc[How Zimlets work] for the short mental model of how a Zimlet gets from your source files to the screen.

[#who-this-guide-is-for]
== Who this guide is for

This guide is for anyone who wants to extend the Modern UI with a new feature. You can be a Zimbra developer or come from outside Zimbra. You need working knowledge of JavaScript and Node.js. Use Preact and JSX for the user interface. The Modern UI is built with Preact, and the Zimlets that Zimbra provides use it. Other frameworks may have limitations. See xref:getting-started/prerequisites.adoc[What you need before you start] for the full list.

If you only deploy a Zimlet that someone else built, you are an administrator. Start with xref:run-package-deploy/deploy.adoc[Deploy].

== What you will build

You build a working Zimlet. You create it from a template, run it in the Modern UI while you develop, and package it as a zip file. You then deploy the zip file to a Zimbra server.
