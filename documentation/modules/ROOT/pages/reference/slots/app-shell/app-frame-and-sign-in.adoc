= App frame and sign-in

The frame of the xref:reference/glossary.adoc#modern-ui[Modern UI] has parts that no single screen owns. Use these slots to run a feature for the whole application and to add screens with routes. They also fill the strip and the panel at the right edge of the window, and they change two dialogs that every user can reach. Choose them when your xref:reference/glossary.adoc#zimlet[Zimlet] adds something to the application as a whole and not to one screen. xref:fundamentals/extending-the-ui.adoc[Slots and handlers] explains how a handler fills a slot.

[#before-you-register-a-handler]
== Before you register a handler

[#right-edge-of-the-screen]
=== Right edge of the screen

The slots `rightbar-50px` and `rightside-zimlet-slot` draw at the right edge of the screens of Mail, Calendar, Contacts and Briefcase. The search screens of Mail and Calendar have them too. They appear only in a window at least 1025 px wide. In Mail, the strip is left of the panel, and the panel is at the right edge of the window.

.The Mail screen with the strip and the panel filled by a Zimlet
image::slots-app-frame-right-edge.png["The Mail screen in a wide window. Outlined in red at the right edge: a narrow strip with the text Bar, and to its right the text Panel of a Zimlet, which is the content of the panel. A Zimlet fills both."]

A Zimlet fills the outlined strip and the outlined text in the panel. The strip has its own background and borders. The panel starts at the strip and reaches the right edge of the window.

You also learn to listen to events of the page and to add a keyboard shortcut. <<rightbar-50px,`rightbar-50px`>> and <<rightside-zimlet-slot,`rightside-zimlet-slot`>> take a component in the same way.

xref:build-by-goal/recipe-sidebar-widget.adoc[Add a sidebar widget]::

[#app]
== app

Adds a component that runs while the Modern UI is open and has no place of its own. Use it for a feature that belongs to no screen, such as a dialog, an overlay or a listener. Use the slot of a screen for content that has a place on that screen.

[#app-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::app', handler)

// handler: ({ matchesScreenMd }) => element | null
----

[#app-props]
=== Props

[[app-matches-screen-md]]pass:[<a class="anchor" href="#app-matches-screen-md"></a>]`matchesScreenMd` (boolean)::
`true` when the window is at least 1025 px wide.

[#app-usage-notes]
=== Usage notes

* The component stays in the page while the user moves between screens.
* The slot does not render on the print screens, which have no header.
* The slot draws nothing of its own. With `?zimletSlots=show`, a label shows where it is. See xref:run-package-deploy/run-and-debug.adoc#debug-slots[Show every slot in the page].
* For a complete example, see xref:build-by-goal/recipe-app-content.adoc[Run an app-wide feature].

[#routes]
== routes

Adds a screen at an address of your own. The Modern UI shows the element that the handler returns when the address of the page matches its `path`. Use it with a tab slot that links to the address, so that users can open the screen. See xref:reference/slots/app-shell/navigation-and-tabs.adoc[Navigation and tabs].

[#routes-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::routes', handler)

// handler: ({ slugs }) => element | null
----

Return an element with a `path` prop, which is the address that opens the screen.

[#routes-props]
=== Props

[[routes-slugs]]pass:[<a class="anchor" href="#routes-slugs"></a>]`slugs` (object)::
The names that the Modern UI uses in addresses, as set in its client configuration. Each key is a name such as `videoapps` and each value is a string. Use it to build the `path`.

[#routes-usage-notes]
=== Usage notes

* The Modern UI checks your route after its own routes and before its error page.
* The slot adds only the screen. Add the tab or the link that opens it with a slot such as xref:reference/slots/app-shell/navigation-and-tabs.adoc#vertical-tab-item[`<vertical>-tab-item`].
* The slot draws nothing of its own. With `?zimletSlots=show` it writes `non-visible ZimletSlot name=routes` to the console and shows no label.
* For a complete example, see xref:build-by-goal/recipe-tab-and-route.adoc[Add a tab and a screen].

[#rightbar-50px]
== rightbar-50px

Adds a narrow strip at the right edge of the screens of Mail, Calendar, Contacts and Briefcase. Use it for a column of small controls, such as icons that open your feature. Use <<rightside-zimlet-slot,`rightside-zimlet-slot`>> for a panel with more room.

[#rightbar-50px-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::rightbar-50px', handler)

// handler: () => element | null
----

[#rightbar-50px-props]
=== Props

None.

[#rightbar-50px-usage-notes]
=== Usage notes

* See <<right-edge-of-the-screen>> for the screens and the window width where the strip shows.
* The strip is up to 50 px wide. It has a background and borders only while a handler returns content. A handler that returns `null` draws no strip.

[#rightside-zimlet-slot]
== rightside-zimlet-slot

Adds a panel at the right edge of the screens of Mail, Calendar, Contacts and Briefcase. Use it for a block that stays in view while the user moves between screens, such as a clock or a status note. Use <<rightbar-50px,`rightbar-50px`>> for a strip of small controls.

[#rightside-zimlet-slot-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::rightside-zimlet-slot', handler)

// handler: () => element | null
----

[#rightside-zimlet-slot-props]
=== Props

None.

[#rightside-zimlet-slot-usage-notes]
=== Usage notes

* See <<right-edge-of-the-screen>> for the screens and the window width where the panel shows.
* The panel is up to 250 px wide and as high as the screen. Other Zimlets can fill it too, so give your block its own border or spacing.
* For a complete example, see xref:build-by-goal/recipe-sidebar-widget.adoc[Add a sidebar widget].

[#change-password-description]
== change-password-description

Adds text above the fields of the *Change Password* dialog. Use it to explain the rules for a new password or to say where users get help.

[#change-password-description-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::change-password-description', handler)

// handler: () => element | null
----

[#change-password-description-props]
=== Props

None.

[#change-password-description-usage-notes]
=== Usage notes

* The dialog opens from the *Change Password* item of the account menu. A deployment that sets an external address for changing passwords opens another dialog, and the slot does not show there.
* The sign-in screen has the same form when the server asks for a new password, but Zimlets load only after the user signs in. A handler does not show on that screen.

[#show-details-notification-button]
== show-details-notification-button

Hides the *Show details* button of the dialog that reports an error. Use it when users must not see the technical text of an error.

WARNING: A handler that returns a value hides the button for every user who has the Zimlet. The error details and the *Copy to clipboard* button, which open from it, are hidden with it. Return `null` when your Zimlet does not apply, and the Modern UI keeps the button.

[#show-details-notification-button-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::show-details-notification-button', handler)

// handler: () => true | null
----

Return `true` to hide the button, or `null` to keep it.

[#show-details-notification-button-props]
=== Props

None.

[#show-details-notification-button-usage-notes]
=== Usage notes

* The Modern UI checks only whether a handler returns a value. It does not draw what the handler returns.
* The dialog opens when the Modern UI reports an error, such as a failed action in Calendar. Its title is *Something went wrong* unless the error sets its own.
