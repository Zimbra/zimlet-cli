= Header menus

The header has two drop-down menus that a xref:reference/glossary.adoc#zimlet[Zimlet] can extend. The *Settings and more* menu opens from the gear icon, and the account menu opens from the avatar. Add a link or an action next to the entries that users already look for there. To hide the *About* or *Language* item, use the slots of xref:reference/slots/hide-built-in-ui.adoc#menus[Hide built-in UI]. The account menu also opens the *Change Password* dialog, which has a slot for text. A narrow window also shows both menus in the header of the sidebar. xref:fundamentals/extending-the-ui.adoc[Slots and handlers] explains how a handler fills a slot.

[#before-you-register-a-handler]
== Before you register a handler

[#settings-and-more-menu]
=== Settings and more menu

From top to bottom, the menu has these groups:

. The slot `settings-dropdown-item`, then *Settings* and *Language* (only with the options feature, and hidden by the slot xref:reference/slots/hide-built-in-ui.adoc#language-link[`language-link`]), *Help* and the slot `settings-dropdown-item-end`.
. The theme options.
. *About*, which xref:reference/slots/hide-built-in-ui.adoc#about-link[`about-link`] hides, and the slot `gear-menu`.

.The *Settings and more* menu without a Zimlet
image::slots-header-menus-settings-menu.png["The Mail screen with the Settings and more menu open from the gear icon. Outlined in red: the whole menu, with Settings, Language and Help, then the three theme options, then About."]

The outlined menu shows the entries of the Modern UI. A Zimlet adds items at the positions in the list.

[#account-menu]
=== Account menu

From top to bottom, the menu has these groups:

. The name and the address of the user.
. *Change Password* (only when the account may change its password), which opens a dialog with the slot `change-password-description`, and *Change Profile Image*.
. The slot `header-menu-item`, then *Logout*.

.The account menu without a Zimlet
image::slots-header-menus-account-menu.png["The Mail screen with the account menu open from the avatar. Outlined in red: the whole menu, with the name and the email address of the user, Change Password and Change Profile Image, then Logout."]

The outlined menu shows the entries of the Modern UI. A Zimlet adds its item above *Logout*.

[#members]
== Members

<<settings-dropdown-item,`settings-dropdown-item`>>::
An item at the top of the first group of the *Settings and more* menu.

<<settings-dropdown-item-end,`settings-dropdown-item-end`>>::
An item at the end of the first group of the *Settings and more* menu, after *Help*.

<<gear-menu,`gear-menu`>>::
An item in the last group of the *Settings and more* menu, below *About*.

<<header-menu-item,`header-menu-item`>>::
An item in the account menu, above *Logout*.

<<change-password-description,`change-password-description`>>::
Text above the fields of the *Change Password* dialog, which opens from the account menu.

[#learn-from-an-example.examples]
== Learn from an example

Each entry is an example that fills slots of this category. Follow one and use it as a model for the other slots.

xref:build-by-goal/recipe-gear-and-settings-menu.adoc[Add menu items to the app]::
A recipe that adds a *Help desk* link and a *Report a problem* action to the *Settings and more* menu with <<settings-dropdown-item-end,`settings-dropdown-item-end`>> and <<gear-menu,`gear-menu`>>. Adds a *Manage account* link to the account menu with <<header-menu-item,`header-menu-item`>>. You learn to choose the menu slot for each item and to build it with `ActionMenuItem`. Every other slot in this category that adds an item is registered the same way. <<change-password-description,`change-password-description`>> adds text, so a handler returns an element and not an `ActionMenuItem`.

[#settings-dropdown-item]
== settings-dropdown-item

Adds an item at the top of the *Settings and more* menu, above *Settings*. Use it when your item must come before the built-in entries. Use <<settings-dropdown-item-end,`settings-dropdown-item-end`>> for an item that belongs after *Help*.

[#settings-dropdown-item-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::settings-dropdown-item', handler)

// handler: () => element | null
----

Return an xref:reference/shims/components/menus.adoc#action-menu-item[`ActionMenuItem`] from `@zimbra-client/components`, so that the item looks like the others in the menu.

[#settings-dropdown-item-props]
=== Props

None.

[#settings-dropdown-item-usage-notes]
=== Usage notes

* Every user sees the items. The slot does not depend on the options feature that controls *Settings* and *Language*.

[#settings-dropdown-item-end]
== settings-dropdown-item-end

Adds an item at the end of the first group of the *Settings and more* menu, after *Help*. Use it for a link or an action that users need about as often as *Help*, such as a link to a help desk. Use <<settings-dropdown-item,`settings-dropdown-item`>> for an item that must come first.

[#settings-dropdown-item-end-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::settings-dropdown-item-end', handler)

// handler: () => element | null
----

Return an xref:reference/shims/components/menus.adoc#action-menu-item[`ActionMenuItem`] from `@zimbra-client/components`, so that the item looks like the others in the menu.

[#settings-dropdown-item-end-props]
=== Props

None.

[#settings-dropdown-item-end-usage-notes]
=== Usage notes

* For a complete example, see xref:build-by-goal/recipe-gear-and-settings-menu.adoc[Add menu items to the app].

[#gear-menu]
== gear-menu

Adds an item in the last group of the *Settings and more* menu, below *About*. Use it for an item that belongs with *About*, such as a feedback form.

[#gear-menu-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::gear-menu', handler)

// handler: () => element | null
----

Return an xref:reference/shims/components/menus.adoc#action-menu-item[`ActionMenuItem`] from `@zimbra-client/components`, so that the item looks like the others in the menu.

[#gear-menu-props]
=== Props

None.

[#gear-menu-usage-notes]
=== Usage notes

* The slot is in the same group as *About*. A handler for xref:reference/slots/hide-built-in-ui.adoc#about-link[`about-link`] hides *About* and also every item of this slot.
* For a complete example, see xref:build-by-goal/recipe-gear-and-settings-menu.adoc[Add menu items to the app].

[#header-menu-item]
== header-menu-item

Adds an item to the account menu, the menu that opens from the avatar of the user in the header. The items appear above *Logout*. Use it for a link that belongs with the account, such as a link to an external page. For the menu behind the gear icon, use <<settings-dropdown-item-end,`settings-dropdown-item-end`>> or <<gear-menu,`gear-menu`>>.

// handler: () => element | null
----

Return an xref:reference/shims/components/menus.adoc#action-menu-item[`ActionMenuItem`] from `@zimbra-client/components`, so that the item looks like the others in the menu.

[#header-menu-item-props]
=== Props

[#header-menu-item-usage-notes]

[#change-password-description]
== change-password-description

Adds text above the fields of the *Change Password* dialog. Use it to explain the rules for a new password or to say where users get help.

[#change-password-description-register-a-handler]
=== Register a handler

[source,js]
----
plugins.register('slot::change-password-description', handler)

// handler: () => element | null
----

[#change-password-description-props]
=== Props

None.

[#change-password-description-usage-notes]
=== Usage notes

* The dialog opens from the *Change Password* item of the account menu. A deployment that sets an external address for changing passwords opens another dialog, and the slot does not show there.
* The sign-in screen has the same form when the server asks for a new password, but Zimlets load only after the user signs in. A handler does not show on that screen.
