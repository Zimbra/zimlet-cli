= Zimlet Extension Point Developer Guide
:toc:
:toclevels: 3
:sectanchors:
:sectlinks:

This guide describes the named `ZimletSlot` extension points and direct `invokePlugin` calls available to Zimlets in the Modern Web client. Each extension point has a stable section link, a concise placement description, and a shared description of its plugin-facing contract.

The former JSON inventory at `zimlet-slot-catalog.json` has not yet been migrated. Until that migration is requested, this AsciiDoc guide is the format for new and updated extension-point documentation; do not infer missing contracts from the legacy inventory.

The source scanner can scaffold sections from statically discovered callsites. Scanner-created sections are explicitly marked incomplete until their plugin contract and placement have been traced.

== Host integration model

`ZimletSlot` obtains the Zimlets manager from context and invokes the registry key `slot::<name>`. The public slot name in this guide omits the `slot::` prefix. Unless the host supplies an explicit `props` object, the remaining slot props are the plugin payload. Function-valued handler results are rendered as Preact elements with that payload; other results are rendered as results. A function child receives the complete result array and replaces default rendering. Handler results are not awaited.

Direct `invokePlugin` calls are separate extension points. Their exact first argument is the invocation name; subsequent arguments and result use are documented in order.

For further host implementation detail, see the link:../rules/zimlet-slot-catalog.md[ZimletSlot and invokePlugin contract].

== Using this guide

Each named slot or direct invocation has its own section. Use the section's stable anchor to link directly to it. The section metadata identifies its exact public name, extension kind, source location or locations, feature/root component, and direct rendering/calling parent.

Slot sections explain the meaning of each shared plugin prop once. They do not list every placement's runtime prop value. When a placement adds a prop or has a materially different contract, the placement description calls out that difference. Source paths use repository-relative locations and 1-based line numbers.
